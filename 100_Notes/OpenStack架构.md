> [!note] 核心
> 通过独立的组件分别管理计算、存储、网络等底层物理资源，并统一通过 **RESTful API** 进行交互与集成

# 核心组件
- **Keystone（身份认证服务）：** 
  - 整个云平台的“看门人”。
  - 负责管理用户、项目、权限，并为其他所有组件提供**认证和授权令牌（Token）**，同时维护服务目录。
- **Nova（计算服务）：** 
  - OpenStack 的“大脑”。
  - 负责管理虚拟机的整个生命周期（创建、调度、销毁），它并不直接提供虚拟化能力，而是通过驱动管理底层的 Hypervisor（如 KVM、Xen 等）。
- **Neutron（网络服务）：** 
  - 负责云平台的网络构建。
  - 提供虚拟交换机、路由器、防火墙、IP 地址分配（DHCP）以及负载均衡等网络服务的管理。
- **Glance（镜像服务）：** 
  - 虚拟机的“模板库”。
  - 负责存储和管理虚拟机的磁盘镜像，当 Nova 需要创建虚拟机时，会从 Glance 下载镜像。
- **Cinder（块存储服务）：** 
  - 为虚拟机提供持久化的“云硬盘”。
  - 支持即插即用，即使虚拟机被销毁，Cinder 上的数据依然存在。
- **Swift（对象存储服务）：** 
  - 用于存储海量非结构化数据（如图片、视频、备份文件等）。
  - 具有极高的容错性、弹性和扩展性，其存储不需要挂载给虚拟机即可直接通过 API 访问。
- **Horizon（仪表盘/Web 界面）：** 
  - 提供了一个可视化的网页控制台，让管理员和最终用户能够通过鼠标点击来轻松申请和管理上述所有资源。

# 通信
|通信机制|作用对象|技术选型示例|说明|
|---|---|---|---|
|**RESTful API**|**组件之间 / 用户与组件**|HTTP/HTTPS|外部用户发起的请求，或者组件与组件之间的高层逻辑调用，均采用公开的标准 API 接口。|
|**AMQP 消息队列**|**组件内部进程之间**|RabbitMQ / Qpid|每个组件（如 Nova）内部有多个子进程，为了实现异步处理和高并发，它们通过消息队列进行内部的数据传递。|
|**数据库**|**状态存储**|MySQL / MariaDB|用于保存云平台的所有配置信息和运行状态（如虚拟机列表、网络拓扑等）。|

# 物理节点
1. **控制节点 (Control Node)：** 运行所有核心管理服务的 API、消息队列（RabbitMQ）和数据库（MySQL），是平台的控制中枢。
2. **计算节点 (Compute Node)：** 真正承载虚拟机运行的物理服务器，主要运行 `nova-compute` 服务及底层的虚拟化软件。
3. **网络节点 (Network Node)：** 专门负责处理进出云平台的数据流量，运行 Neutron 服务，负责 NAT、路由和 DHCP 等网络流量的分发。
4. **存储节点 (Storage Node)：** 专用于部署 Cinder 或 Swift 服务的物理服务器，提供磁盘阵列或分布式存储集群。
